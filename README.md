# issue-triaging-agent-digests

Output repository for [`issue-triaging-agent`](https://github.com/virchan/issue-triaging-agent).

Each issue in this repository is a machine-generated triage digest published automatically by that pipeline.

## Not Affiliated with scikit-learn

**This repository is not affiliated with, endorsed by, or operated on behalf of the scikit-learn organisation, Probabl, INRIA, or NumFOCUS.**

Every issue in this repository is generated by an LLM reading scikit-learn's **public** "Needs Triage" issues via GitHub's read-only API. Nothing here is written to, or on behalf of, the scikit-learn repository.

The author is also a scikit-learn contributor, but this project is separate from that work, and neither acts on behalf of the project nor its maintainers.

## What This Repository Contains

This repository contains no application code.

It receives daily triage digests generated by `issue-triaging-agent`, where the pipeline, architecture, evaluation, and deployment are documented.

Each digest covers one polling window and contains scikit-learn issues newly labelled "Needs Triage" since the previous run, grouped by priority. See "How to Read a Digest" below for what each entry shows.

If a polling window contains no new issues, the pipeline instead selects older open "Needs Triage" issues from the backlog.

## How to Read a Digest

| Field | Description |
| --- | --- |
| **Suggested label** | The label the model thinks fits, constrained to the repository's real current label list. |
| **Confidence** | The model's own confidence score. |
| **Contains a code snippet** | Whether the original issue body includes a code block. |
| **Possibly related to** | Shown only when found — the most similar other issue above a minimum similarity floor, with its similarity score. A suggestion, not a duplicate/not-duplicate classification. |
| **Summary & rationale** | A one-line summary plus a longer rationale explaining the judgment. |
| **Spam flag** | A ⚠️ marker shown next to the title when the model flags the issue as possible spam. |

## Review Workflow

The author reviews each digest and can add corrections in the issue comments.

A correction references the corresponding scikit-learn issue, for example: `scikit-learn/scikit-learn#12345`.

Short aliases supported by the pipeline can also be used.

Closing the digest triggers the review workflow:

1. Parse corrections from the comment thread.
1. Match each correction to its corresponding judgement.
1. Record the correction as the reviewed outcome.
1. Where API quota permits, re-run the judgement with the correction included as additional context.
1. Publish an acknowledgement describing which corrections were recorded, applied, or could not be matched.
1. Mark the digest as reviewed.

Reviewed judgements, including corrections and confirmations, can later be retrieved as few-shot examples for future model calls.

This allows real reviewed outcomes to become part of the system's future context rather than keeping corrections only as an audit log.

## Labels

* `daily digest` — every published digest
* `manually-triggered` — a digest published via the pipeline's on-demand trigger rather than the scheduled daily run

## Issues and Pull Requests

Restricted to collaborators. This repo is a generated output feed, not a place to file issues about scikit-learn itself.

If you have feedback on a scikit-learn issue's actual triage, that belongs upstream, not here.

## AI Disclosure

The triage judgements in this repository are generated by LLM rather than by a human triager.

Generated content includes suggested labels, priorities, confidence scores, summaries, rationales, spam flags, and possible related-issue suggestions.

The output should therefore be treated as model-generated assistance for human review rather than as an authoritative scikit-learn triage decision.
